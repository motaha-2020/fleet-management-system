## 1. القرارات

| # | الموضوع | القرار |
|---|---|---|
| D1 | الأدوار | أدمن المنصة، مدير الشركة، مدير الأسطول، المدير المالي، السواق. **دور المشاهد (`viewer`) يُحذف** |
| D2 | من يعدّل الصلاحيات | **مدير الشركة** يعدّل صلاحيات أدوار شركته من صفحة إعدادات |
| D3 | أدوار مخصصة | مسموح بإنشاء أدوار بأسماء جديدة (عربي/إنجليزي) لكل شركة |
| D4 | شخص بأكثر من دور | مسموح، و**لكل دور فروعه** (مثال: مدير أسطول لفرع القاهرة + مالي للشركة كلها) |
| D5 | مدير الأسطول | محصور في فروع محددة |

| D7 | حدود صفحة الصلاحيات | السواق لا يأخذ صلاحيات مكتب · لا دور غير مدير الشركة يدير المستخدمين والصلاحيات · مدير الشركة لا يستطيع سحب صلاحياته من نفسه |
| D8 | السواق | دور ثابت لا يُعدَّل من صفحة الصلاحيات (دخول مختلف: كود تفعيل + PIN). يستخدم الموبايل أو نسخة ويب مطابقة للموبايل |
| D9 | ملف الشركة | مدير الشركة يعدّله: اللوجو، العنوان، التليفون، الإيميل، السجل التجاري، الرقم الضريبي (+ العملة والتوقيت الموجودين) |
| D10 | ملف الإداري | الاسم، الإيميل، الهاتف، المسمى الوظيفي |
| D11 | إنشاء الشركات | **تسجيل ذاتي**، والشركة تشتغل فورًا بدون موافقة الأدمن |
| D12 | الاشتراكات والباقات | لا يوجد. المنصة داخلية في المرحلة الحالية |

| D13 | إظهار كلمة السر | زر إظهار/إخفاء في كل خانة كلمة سر (موجود في الويب، ويُضاف لصفحة التسجيل) |
| D14 | استعادة الحساب | نسيت كلمة السر **أو اسم الدخول**: رابط/رسالة على الإيميل · أو مدير الشركة/الأدمن يعطي **كود دخول مؤقت**، وبعد الدخول به يُجبر على تغيير كلمة السر |
| D15 | التسجيل | مدير الشركة يسجّل بنفسه ويضبط شركته ويعمل حسابات باقي المستخدمين · السواقين يعملهم مدير الشركة/الأسطول |
| D16 | العملاء | بيانات فقط بدون دخول. العميل يُحدَّد من **التاسك** (عميل واحد لكل تاسك) |
| D17 | التاسك | ينشئها مدير الحركة. نوعان: **رحلة** (من مكان لمكان، وقت، كم) أو **فترة** (أيام / يومي / من تاريخ-وقت إلى تاريخ-وقت). فيها عربية وسواق أو أكثر. السواق يراها ويبدأها وينهيها من الموبايل بصورة عداد في البداية والنهاية. تحتاج اعتماد مدير الحركة |
| D18 | الاستبدال أثناء التاسك | "سطور تنفيذ": كل سطر = عربية + سواق + من/إلى. العطل أو تغيير السواق يقفل السطر بسبب وصورة عداد ويفتح سطرًا جديدًا. التاسك والعميل لا يتغيران. تكلفة إصلاح العطل **على الشركة** لا على العميل |
| D19 | الاعتماد | قراءات العداد (ومنها عداد التفويل)، الفواتير/التكاليف، الصيانة، الفحص، التاسكات: **لا تُحتسب إلا بعد اعتماد مدير الحركة**. إجباري افتراضيًا، ومدير الشركة يستطيع جعل نوع ما تلقائيًا من الإعدادات. إن كان مدير الحركة هو المسجِّل ← **يعتمد مدير الشركة**. الفواتير المالية: مدير الحركة فقط |
| D20 | قراءة العداد من الصورة | **على الموبايل** (بدون إنترنت). السواق يؤكد الرقم. المراجع يرى علامة "مطابق للصورة / مختلف" |
| D21 | فحص العربيات | فحص مستقل (بنود + صور) ومدته في الإعدادات، ويحتاج اعتماد |
| D22 | البيانات الحالية | كلها تجريبية على الـ Staging ولا تحتاج ترحيل للاعتماد |
| D23 | التجربة | كل شيء يُجرَّب ببيانات وهمية (Fake) لنرى المشاكل |

### قرارات افتراضية (لم يعترض عليها المالك)
- **Q1** ميزانيات الوقود: يعدّلها **مدير الشركة**، والمالي يعرض فقط (اتساقًا مع D6).
- **Q2** حماية التسجيل الذاتي: تأكيد الإيميل بكود + حد للمحاولات من نفس الإيميل/العنوان.
- **Q3** الشخص بدورين: **يبدّل بين أدواره** (الوضع الحالي SEC-002)، ولا تُجمع الصلاحيات.

## 3. قاعدة البيانات

### 3.1 الوضع الحالي

| الجدول | القاعدة | المحتوى |
|---|---|---|
| `identities` | المنصة | الدخول لكل المستخدمين |
| `memberships` | المنصة | الشركة + **دور واحد** + الفروع (+ `driver_id` للسواق) |
| `drivers` | الشركة | ملف السواق ✅ |
| — | — | لا يوجد ملف للإداري ❌ |
| `RBAC_MATRIX` | كود (`packages/config/src/rbac.ts`) | الصلاحيات ثابتة، تغييرها يحتاج نشر |

### 3.2 المقترح

**السواقين (قاعدة الشركة):** `drivers` وجداول الأجهزة كما هي.

**الإدارة (قاعدة الشركة):**

| الجدول | الأعمدة الأساسية |
|---|---|
| `staff` | `id`, `identity_id`, `full_name`, `email`, `phone`, `job_title`, `status`, timestamps |
| `roles` | `id`, `key` (للأدوار الافتراضية), `name_ar`, `name_en`, `is_system`, `is_locked`, `status` |
| `role_permissions` | `role_id`, `action`, `scope` (`all` / `branches`) |
| `staff_roles` | `staff_id`, `role_id`, `branch_ids[]` (فروع هذا الدور لهذا الشخص) |

**الشركة (قاعدة الشركة):** توسعة `company` بـ `logo_file_id`, `address`, `phone`, `email`, `commercial_register`, `tax_number`.

**المنصة:** `identities` للدخول فقط. `memberships` يبقى للربط بين الشخص والشركة، ويُحذف منه عمود `role`.

**`RBAC_MATRIX`** في الكود يصبح القيم الافتراضية التي تُنسخ إلى `role_permissions` عند إنشاء الشركة. قائمة `ACTIONS` تبقى في الكود (الصلاحيات الممكنة يحددها الكود، وقيمها تحددها الشركة).

### 3.3 الترحيل
- كل `membership` غير سائق ← `staff` + سطر في `staff_roles` بنفس الدور والفروع.
- مستخدمو `viewer` الحاليون (إن وُجدوا على Staging) ← قرار: يُحذفون أو يُنقلون لدور مخصص "مشاهد".
- اختبارات RBAC المولَّدة (211 اختبار) تُبنى على المصفوفة الافتراضية + اختبارات للتعديل والخانات المقفولة.

## 6. الاعتمادات (D19)

| النوع | اليوم | المطلوب |
|---|---|---|
| قراءة العداد | تُحتسب فورًا | `pending` ← `approved`/`rejected` |
| الوقود | يُقبل تلقائيًا إلا المشكوك فيه | كل تفويل `pending` |
| التكاليف/الفواتير | تُحتسب فورًا | `pending` |
| زيارات الصيانة | مسودة ← مكتملة | مكتملة ← `approved` |
| الفحص | غير موجود | `pending` |
| التاسك | غير موجودة | `pending` عند الإنهاء |

- شاشة **اعتمادات موحدة** لمدير الحركة: كل المعلّق بفروعه، بالصور، اعتماد/رفض بسبب، واعتماد مجموعة.
- المسجِّل ≠ المعتمِد. إن كان المسجِّل مدير الحركة يظهر البند لمدير الشركة.
- الرفض يصل للسواق إشعارًا.
- التقارير ولوحة المتابعة تحتسب المعتمد فقط، وتعرض المعلّق رقمًا منفصلًا.
- إعداد لكل نوع: `manual` (افتراضي) / `auto`.

## 7. العملاء والتاسكات (D16–D18)

| الجدول | الأعمدة الأساسية |
|---|---|
| `customers` | `name`, `contact_name`, `phone`, `email`, `status` |
| `tasks` | `customer_id`, `kind` (`trip`/`period`), `title`, `from_place`, `to_place`, `starts_at`, `ends_at`, `schedule` (أيام/يومي), `branch_id`, `status` (`planned`/`in_progress`/`done`/`approved`/`rejected`/`cancelled`) |
| `task_lines` | `task_id`, `vehicle_id`, `driver_id`, `started_at`, `ended_at`, `start_reading_id`, `end_reading_id`, `end_reason` (`done`/`breakdown`/`driver_change`/`other`), `note` |

- لا يجوز لنفس العربية أو السواق سطران متداخلان في الوقت.
- عند العطل: تنبيه لمدير الحركة مرتبط بالتاسك + قائمة العربيات الجاهزة والفاضية في الفترة.
- وقت التوقف بين نهاية سطر وبداية بديله يُسجَّل ويظهر في التقارير.
- الكم والوقود والتكاليف خلال سطور التاسك تُنسب لعميلها؛ تكلفة إصلاح العطل لا تُنسب للعميل.
