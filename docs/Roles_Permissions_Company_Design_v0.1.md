## 1. القرارات

| # | الموضوع | القرار |
|---|---|---|
| D1 | الأدوار | أدمن المنصة، مدير الشركة، مدير الأسطول، المدير المالي، السواق. **دور المشاهد (`viewer`) يُحذف** |
| D2 | من يعدّل الصلاحيات | **مدير الشركة** يعدّل صلاحيات أدوار شركته من صفحة إعدادات |
| D3 | أدوار مخصصة | مسموح بإنشاء أدوار بأسماء جديدة (عربي/إنجليزي) لكل شركة |
| D4 | شخص بأكثر من دور | مسموح، و**لكل دور فروعه** (مثال: مدير أسطول لفرع القاهرة + مالي للشركة كلها) |
| D5 | مدير الأسطول | محصور في فروع محددة |
| D6 | المدير المالي | عرض + تصدير Excel للبيانات والتكاليف + **اعتماد التصحيحات المالية**. بدون تعديل |
| D7 | حدود صفحة الصلاحيات | السواق لا يأخذ صلاحيات مكتب · لا دور غير مدير الشركة يدير المستخدمين والصلاحيات · مدير الشركة لا يستطيع سحب صلاحياته من نفسه |
| D8 | السواق | دور ثابت لا يُعدَّل من صفحة الصلاحيات (دخول مختلف: كود تفعيل + PIN). يستخدم الموبايل أو نسخة ويب مطابقة للموبايل |
| D9 | ملف الشركة | مدير الشركة يعدّله: اللوجو، العنوان، التليفون، الإيميل، السجل التجاري، الرقم الضريبي (+ العملة والتوقيت الموجودين) |
| D10 | ملف الإداري | الاسم، الإيميل، الهاتف، المسمى الوظيفي |
| D11 | إنشاء الشركات | **تسجيل ذاتي**، والشركة تشتغل فورًا بدون موافقة الأدمن |
| D12 | الاشتراكات والباقات | لا يوجد. المنصة داخلية في المرحلة الحالية |

### أسئلة مفتوحة
- **Q1** ميزانيات الوقود: يعدّلها المالي أم مدير الشركة فقط؟
- **Q2** حماية التسجيل الذاتي: يكفي تأكيد الإيميل + حد للمحاولات؟ أم أيضًا قصره على دومين إيميل أو رابط تسجيل خاص؟
- **Q3** الشخص بدورين: يرى **مجموع** صلاحيات أدواره معًا، أم يبدّل بين الأدوار (الوضع الحالي: "دور نشط واحد" SEC-002 مع Role Switcher)؟

## 3. قاعدة البيانات

### 3.1 الوضع الحالي

| الجدول | القاعدة | المحتوى |
|---|---|---|
| `identities` | المنصة | الدخول لكل المستخدمين |
| `memberships` | المنصة | الشركة + **دور واحد** + الفروع (+ `driver_id` للسواق) |
| `drivers` | الشركة | ملف السواق ✅ |
| — | — | لا يوجد ملف للإداري ❌ |
| `RBAC_MATRIX` | كود (`packages/config/src/rbac.ts`) | الصلاحيات ثابتة، تغييرها يحتاج نشر |

### 3.2 المقترح

**السواقين (قاعدة الشركة):** `drivers` وجداول الأجهزة كما هي.

**الإدارة (قاعدة الشركة):**

| الجدول | الأعمدة الأساسية |
|---|---|
| `staff` | `id`, `identity_id`, `full_name`, `email`, `phone`, `job_title`, `status`, timestamps |
| `roles` | `id`, `key` (للأدوار الافتراضية), `name_ar`, `name_en`, `is_system`, `is_locked`, `status` |
| `role_permissions` | `role_id`, `action`, `scope` (`all` / `branches`) |
| `staff_roles` | `staff_id`, `role_id`, `branch_ids[]` (فروع هذا الدور لهذا الشخص) |

**الشركة (قاعدة الشركة):** توسعة `company` بـ `logo_file_id`, `address`, `phone`, `email`, `commercial_register`, `tax_number`.

**المنصة:** `identities` للدخول فقط. `memberships` يبقى للربط بين الشخص والشركة، ويُحذف منه عمود `role`.

**`RBAC_MATRIX`** في الكود يصبح القيم الافتراضية التي تُنسخ إلى `role_permissions` عند إنشاء الشركة. قائمة `ACTIONS` تبقى في الكود (الصلاحيات الممكنة يحددها الكود، وقيمها تحددها الشركة).

### 3.3 الترحيل
- كل `membership` غير سائق ← `staff` + سطر في `staff_roles` بنفس الدور والفروع.
- مستخدمو `viewer` الحاليون (إن وُجدوا على Staging) ← قرار: يُحذفون أو يُنقلون لدور مخصص "مشاهد".
- اختبارات RBAC المولَّدة (211 اختبار) تُبنى على المصفوفة الافتراضية + اختبارات للتعديل والخانات المقفولة.
